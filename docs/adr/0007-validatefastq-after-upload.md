# 上传完成后检查 FASTQ 记录

分片上传的字节是否原样到达，仍由 SHA-256 决定。SHA-256 一致之后、文件进入可分析状态之前：若文件名以 `.gz` 结尾，先做完整 gzip 读取；再用镜像里的 ValidateFastq 0.1.1 检查这一份 FASTQ 的记录。OpenJDK 8 随该工具安装。

ValidateFastq 0.1.1 在记录不合格时仍可能以退出码 0 结束，因此还要求输出含 `no errors found`，并且不能出现按 read 编号报出的错误。创建任务或重新分析前，再核对 R1/R2 的记录数量与 read 编号配对。任一步不合格时文件不可分析，不启动组装；校验日志保留在临时目录或任务日志目录。
