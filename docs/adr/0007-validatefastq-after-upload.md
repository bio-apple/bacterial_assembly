# 上传完成后用 ValidateFastq 检查记录

分片上传的字节是否原样到达，仍由 SHA-256 决定。SHA-256 一致之后、文件进入可分析状态之前，再用镜像里的 ValidateFastq 0.1.1 检查这一份 FASTQ 的记录。OpenJDK 8 随这个工具装进目前没有 Java 的镜像。

0.1.1 在记录不合格时写日志后仍以退出码 0 结束。只看退出码会放行坏文件，所以还要求日志里出现「没有错误」，并且不能出现按 read 编号报出的错误。不合格的文件留在暂存，不进入已校验目录，也不进入分析任务的输入。直接随任务提交的文件在排队前走同一次检查。
